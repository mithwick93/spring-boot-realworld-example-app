**Preserved:** `CursorPageParameter`'s public API is unchanged — same constructor, `getLimit()`/`isNext()`/`getQueryLimit()`, and the Lombok-generated accessors MyBatis's OGNL binds against. `LimitClamp`'s structural boundaries from PR #1 (Extract Method → Isolate Dependency → Extract Class) are untouched; only `LimitClamp.resolve`'s non-positive branch changed.

**Risked:** The two existing characterization tests pinned the old fallback-to-default behavior; flipping their assertions instead of adding new ones meant a diff reviewer could mistake the change for a broken regression rather than an intentional re-purposing from characterization to specification. A real behavior change for any GraphQL caller currently sending `first`/`last` of 0 or negative and expecting the old default-of-20 fallback — traced all 12 real call sites (`ArticleDatafetcher.java`, `CommentDatafetcher.java`) and confirmed none hardcodes such a value; the residual risk is external client behavior, not visible from the codebase.

**Mitigated:** Chose floor-clamp-to-1 over throwing or logging specifically because it's symmetric with the existing over-limit clamp-to-`MAX_LIMIT` behavior and matches REST's own `@Min(1)` floor convention on the sibling `ArticlesApi.java` path — smallest change, no new dependencies, no exception plumbing through `GraphQLCustomizeExceptionHandler` (confirmed it has no branch for a generic exception type, which would otherwise fall through to an opaque internal-error shape). Both renamed tests confirmed red before the fix, green after; full 107-test suite green afterward — same total as baseline, no tests added or removed, only re-purposed. Commit `4566437`.
